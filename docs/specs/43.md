## 배경과 목적
실황 수업 화면에 들어오면 진행 중인 스크립트를 마지막 컷(last cut idx)까지 따라잡아 재생합니다. 이때 처음부터 재생하지 않고, last cut idx 직전의 가장 가까운 리셋 컷부터 재생해야 합니다. 요구사항은 리셋 컷을 actionType 'CLEAN' 또는 'CLEAR'로 정의합니다. 그런데 지금 `parseDocument`(src/index.ts)는 contents에 ADD/MODIFY/CLEAN_SCENE/CLEAN/POPUP/MEMO/BACKGROUND/MAGNIFY만 남기고 'CLEAR' 컷은 버립니다. `findNearestCleanBefore`, `fastforward`, `playToPoint`(src/player.ts)도 CLEAN/CLEAN_SCENE/BACKGROUND만 리셋 지점으로 봅니다. tutor-web과 student-app이 같은 기준을 쓰도록 리셋 컷 판정을 공용 함수로 노출하고 CLEAR를 지원합니다.

## 범위
하는 것
- 리셋 컷 판정 함수와 상수를 공개 API로 추가합니다.
- `parseDocument`가 CLEAR 컷을 contents에 남기고, refreshPoints와 curtains에도 CLEAN과 똑같이 반영합니다.
- `findNearestCleanBefore`, `fastforward`, `playToPoint`가 CLEAR를 CLEAN과 똑같이 다룹니다.
- 버전을 1.5.0으로 올리고 git tag v1.5.0을 답니다.

하지 않는 것
- 재생 타이밍(sleep 값), 돋보기, 프롤로그/에필로그 순서는 바꾸지 않습니다.
- 앱과 웹의 호출부는 각 프로젝트 스펙에서 다룹니다.

## 변경할 동작
1. `src/player.ts`에 다음을 추가하고 `src/index.ts`에서 export합니다.
   - `RESET_ACTION_TYPES = ['CLEAN','CLEAN_SCENE','CLEAR'] as const`
   - `isResetCut(cut: unknown): boolean`: actionType을 대문자로 바꾼 값이 RESET_ACTION_TYPES에 있으면 true입니다.
2. `findNearestCleanBefore(cuts, targetIdx)`는 `targetIdx-1`부터 0까지 거꾸로 훑습니다. `isResetCut(cut)`이거나 actionType이 'BACKGROUND'인 첫 인덱스를 돌려주고, 없으면 0을 돌려줍니다. targetIdx 자신은 보지 않습니다(지금과 같음).
3. `fastforward`와 `playToPoint`의 반복문에서 `actionType === 'CLEAN' || 'CLEAN_SCENE' || 'BACKGROUND'` 분기를 `isResetCut(cut) || actionType==='BACKGROUND'`로 바꿉니다. 리셋 컷은 runCut만 실행하고 continue합니다.
4. `fastforward`는 지금처럼 `callbacks.runCurtains(startIdx)`를 반복문 전에 호출합니다. 여기서 startIdx는 contents 기준 인덱스입니다.
5. `parseDocument`
   - contents에 남기는 조건에 'CLEAR'를 추가합니다.
   - 두 번째 루프에서 `isResetCut(item)`이면 `persistenceStufs.push({seq:i, objs:[...stackedBack]})`와 `refreshPoints.push(i)`를 실행합니다.
   - 저수준 파서의 scenes/rawStory/persitence 분기(약 290행, 351행)에도 'CLEAR'를 CLEAN과 똑같이 추가합니다.
6. README의 fastforward 설명에 CLEAR를 추가합니다.

## API 계약
공개 API(npm `@qoolla/script-parser`, github tag `v1.5.0`)
- `export const RESET_ACTION_TYPES: readonly ['CLEAN','CLEAN_SCENE','CLEAR']`
- `export function isResetCut(cut: unknown): boolean`
- `findNearestCleanBefore(cuts: unknown[], targetIdx: number): number`: targetIdx보다 작은 인덱스 중 리셋 컷이나 BACKGROUND인 가장 큰 인덱스입니다. 없으면 0입니다.
- `fastforward(cutContents, targetGuide, callbacks)`: 시그니처는 그대로입니다. findNearestCleanBefore 위치부터 targetGuide.studyIdx/step까지 재생합니다. 시작 전에 `callbacks.runCurtains?.(startIdx)`를 한 번 호출합니다.
- `parseDocument(raw)`의 `GuideScript.refreshPoints`와 `GuideScript.curtains[].seq`에 CLEAR 컷의 contents 인덱스가 들어갑니다. `curtains[].objs`는 그 시점까지 쌓인 backgroundSubs 객체 id이고, 객체 본문은 `canvasBackStuffs[id]`에 있습니다.

## 수용 기준
- `isResetCut({actionType:'CLEAN'})`, `isResetCut({actionType:'clean_scene'})`, `isResetCut({actionType:'CLEAR'})`는 true입니다. `isResetCut({actionType:'ADD'})`, `isResetCut({actionType:'BACKGROUND'})`, `isResetCut(null)`은 false입니다.
- cuts=[BACKGROUND, ADD, CLEAR, ADD, ADD]일 때 `findNearestCleanBefore(cuts,4)`는 2입니다.
- cuts=[BACKGROUND, ADD, CLEAN, ADD, CLEAR, ADD]일 때 `findNearestCleanBefore(cuts,5)`는 4이고 `findNearestCleanBefore(cuts,4)`는 2입니다.
- 리셋 컷이 없는 cuts=[BACKGROUND, ADD, ADD]에서 `findNearestCleanBefore(cuts,2)`는 0입니다.
- `fastforward`를 cuts=[BACKGROUND, ADD a, CLEAN, ADD b, ADD c]와 {studyIdx:4, step:'main'}으로 실행하면 runCut이 인덱스 2, 3, 4 순서로만 호출되고 0과 1은 호출되지 않습니다. runCurtains는 인자 2로 정확히 한 번, 첫 runCut보다 먼저 호출됩니다.
- 위 예시에서 CLEAN을 CLEAR로 바꿔도 결과가 같습니다.
- raw 스크립트에 actionType 'CLEAR' 컷이 있으면 `parseDocument` 결과 contents에 그 컷이 있습니다. 그 contents 인덱스는 refreshPoints와 curtains[].seq에 들어 있습니다.
- 기존 CLEAN/CLEAN_SCENE 스크립트를 parseDocument한 결과(contents, refreshPoints, curtains)는 변경 전과 같습니다. 기존 테스트가 모두 통과합니다.
- package.json version이 1.5.0이고 빌드 산출물(dist)에 isResetCut과 RESET_ACTION_TYPES가 export됩니다.

## 가정
- 'CLEAR'는 CLEAN과 의미가 같은 리셋 컷(배경 유지 객체를 뺀 모든 객체 제거)으로 봅니다.
- BACKGROUND도 지금처럼 재생 시작 지점 후보로 둡니다.
