## 배경과 목적
프로젝트 안의 컴포넌트 이름을 하나로 정해 두면 단축키처럼 쓸 수 있습니다. 사람이 프롬프트에서 이름만 말해도 task agent가 해당 파일을 바로 찾게 하는 것이 목적입니다. qoolla-package(Qoolla 공용 npm 패키지, script JSON 파싱 등, /Users/jaesung/QoollaWorkspace/qoolla-package)가 내보내는 공용 모듈과 함수를 `컴포넌트명: 파일경로` 형식의 용어집으로 정리합니다.

## 범위
### 하는 것
- 저장소 루트에 `docs/COMPONENTS.md`를 새로 만듭니다.
- 다음을 뽑아 정리합니다.
  - 패키지 진입점(package.json main/exports)
  - 진입점에서 export되는 모든 공용 함수/클래스/타입과 그것이 정의된 소스 파일
  - 내부 핵심 모듈(script JSON 파서 등)
  - 빌드 설정
  - 테스트 위치
- 루트에 `CLAUDE.md`를 만들고, 용어집 참조와 갱신 규칙을 적습니다. 갱신 규칙에는 'export를 추가하거나 변경하면 갱신한다'를 포함합니다.

### 하지 않는 것
- 코드와 export 변경은 하지 않습니다.
- 이 패키지를 쓰는 다른 프로젝트 문서는 수정하지 않습니다.
- node_modules와 dist 산출물은 넣지 않습니다.

## 변경할 동작
1. 맨 위에 사용법 단락을 두고, 범주별 절로 나눕니다: 진입점 / 공개 API(export) / 내부 모듈 / 빌드·테스트.
2. 항목 형식은 `- **컴포넌트명**: \`소스 상대경로\``입니다. 공개 API 항목은 설명에 한 줄 시그니처나 용도를 적습니다.
3. 컴포넌트명은 export 이름을 그대로 씁니다.

## 수용 기준
- `docs/COMPONENTS.md`가 있고, 모든 항목이 `- **이름**: \`경로\`` 형식이다.
- 적힌 경로는 모두 실제로 존재하는 소스 파일이다. dist 경로는 없다.
- 이름이 중복되지 않는다.
- 패키지 진입점에서 export되는 모든 이름이 '공개 API' 절에 실려 있다.
- node_modules 경로가 없다.
- 루트 `CLAUDE.md`에 용어집 참조와 갱신 규칙이 있다.
- 위 두 파일 외의 파일은 바뀌지 않았다.

## 가정
- 기존 에이전트 지침 파일이 없어서 CLAUDE.md를 새로 만듭니다.
- 경로는 빌드 산출물이 아니라 소스 파일을 가리킵니다.
